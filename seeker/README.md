# Seeker — браузерный клиент BYOND

Шлюз на Node.js подключается к Dream Daemon по нативному протоколу DreamSeeker (как гость) и передаёт
разобранное состояние мира в браузер по WebSocket. Иконки и звуки шлюз берёт из `.rsc` мира, если тот лежит
рядом (`--rsc`), а чего там нет — загружает с сервера, как DreamSeeker, и хранит в папке `cache/`. Поэтому
шлюз может подключаться к любому серверу, в том числе чужому.

## Запуск

Двойной клик по `start.bat` (пути и порты — в `config.json`): он поднимает Dream Daemon, если тот ещё
не слушает порт, затем шлюз, и печатает адреса для браузера. Если процесс шлюза завершится (например, его
убили, чтобы подхватить новый код), лаунчер сам запустит его снова, а раунд продолжится. Вручную:

    npm install
    node server.js --dd 127.0.0.1:51984 --rsc путь\к\paradise.rsc --rsc путь\к\paradise.dyn.rsc --port 8080

Затем открыть `http://<адрес-машины>:8080/` в любом браузере. `SEEKER_DEBUG=1` печатает трафик.

Папка `seeker` самодостаточна: чтобы отдать клиент другому человеку, достаточно её одной (без `cache/`,
`node_modules/` и `*.log`); нужен Node.js 18+, `start.bat` сам поставит зависимости.

### Подключение к серверу на другой машине

В `config.json` вместо `dmb` укажите адрес сервера — Dream Daemon тогда не запускается, а иконки и звуки
загружаются с сервера при первом показе и дальше берутся из `cache/`:

    { "server": "адрес.сервера:порт", "webPort": 8080 }

Вручную — без `--rsc`: `node server.js --dd адрес.сервера:порт --port 8080` (папку кэша меняет `--cache путь`).
Сервер должен пускать гостей.

### Выбор сервера на странице

Если в `config.json` нет ни `dmb`, ни `server` (вручную — без `--dd`), страница сама спрашивает адрес
(`byond://адрес:порт` или `адрес:порт`), помнит недавние, а кнопка «⇄ адрес» вверху переключает сервер.
Ссылкой `http://<шлюз>:8080/?server=адрес:порт` можно сразу поделиться.

    { "webPort": 8080 }

Поле «Параметры подключения» — то же, что `?…` в ссылке `byond://адрес:порт?…` у DreamSeeker: сервер получает их при
входе (в `client/New`), например токен лаунчера `launcher_token=…`. Можно вставить ссылку целиком в поле адреса —
часть после `?` сама перейдёт в параметры. Параметры не попадают в адрес страницы и историю браузера: они хранятся
только в этой вкладке и уходят шлюзу при подключении; в «Недавних» запоминаются только адреса.

## Что работает

- карта в окне вида (`world.view`): турфы, объекты, мобы, `vis_contents`, иконки DMI (состояния,
  направления, анимация), слои и plane, оверлеи/андерлеи, цвет и альфа;
- освещение SS13: объекты освещения с `color_matrix`, умноженные на картинку (кнопка «☀ свет» выключает);
- смена турфов на ходу (стены, пол, сглаживание), `client.images` (HUD-значки, прогресс-бары), `flick()`,
  `transform` (лежащие мобы, повёрнутые предметы), `maptext` (табло, надписи, текст над головами);
- звук `sound()`: каналы, громкость, повтор, остановка, частота, позиция с затуханием и панорамой (кнопка «♪ звук»
  выключает; браузер включает звук после первого клика или нажатия клавиши);
- `invisibility`/`see_invisible` (призраки, метки спавна и прочее невидимое не показываются), направление мобов,
  `mouse_opacity` и клики по растянутым `transform` спрайтам (панели хранилищ);
- перетаскивание мышью (MouseDrag/MouseDrop); контекстное меню глаголов по правой кнопке — когда карта в режиме
  меню (`right-click=false`, у призраков) или с зажатым Shift (SS13), иначе правый клик уходит серверу;
- скольжение при шаге на соседнюю клетку (и камеры за своим мобом), анимации DMI с `loop`/`rewind`;
- HUD (`client.screen`) по `screen_loc`, клики по HUD и карте (выбор атома по пикселю, модификаторы, ПКМ);
- окна `browse()` и tgui: лобби, статпанель, tgui-окна, `output()`, `winset`/`winget`, передача файлов (159),
  `browse(…, "file=…")`, Topic через XHR, псевдонимы ассетов tgui;
- чат: свой чат мира (tgui chat SS13, с хранилищем `hubStorage` поверх `localStorage`), а без него — обычный вывод, командная строка (`say "текст"`, `byond://?…`), tgui-say (клавиша T);
- диалоги BYOND `alert()` и `input()` (текст, число, сообщение, цвет, пароль, выбор из списка, выбор моба/объекта);
- макросы клавиш, которые сервер задаёт через `winset` (Escape, Tab…), и команды `.output`/`.winset` в `command=`;
- клавиши через `keyDown`/`keyUp` (SS13) или встроенное движение;
- автопереподключение страницы, если шлюз перезапустился.

## Отдельные окна

Кнопка «⧉ окна» (включена по умолчанию) открывает окна tgui и `browse()` отдельными окнами браузера — их можно
двигать куда угодно, хоть на другой монитор. Браузер открывает такое окно только сразу после клика или клавиши
(почти все окна открываются именно так) или всегда, если разрешить сайту всплывающие окна (значок в адресной
строке). Заблокированное окно открывается на странице, как раньше. Закрыть отдельное окно крестиком — то же, что
кнопка закрытия tgui. Иконки в tgui (`DmIcon`, ссылки `[0xc…]?state=…`) шлюз рисует сам, как DreamSeeker.

## Отладочный режим (только для админов шлюза)

Игроки не видят кнопку «☀ свет» (выключение освещения — по сути fullbright). Админам шлюза доступны она и
«⏺ запись»: запись сессии для разбора ошибок. Пока запись идёт, шлюз сохраняет все сообщения к игровому серверу и
от него, а страница — всё, что получила от шлюза и отправила ему, ошибки консоли, действия мыши и снимок своего
состояния каждые 5 секунд (с картинкой карты каждые 30). «⏹ стоп» скачивает один файл `seeker-record-….json`,
копия остаётся у шлюза в папке `records/`. Этот файл можно присылать разработчику.

Админ шлюза — тот, кто открыл страницу на той же машине, где работает шлюз, или тот, кто знает токен:

    { "adminToken": "длинная-случайная-строка" }      в config.json (или --admin-token / SEEKER_ADMIN_TOKEN)

Админ открывает страницу один раз как `http://адрес/?admin=<токен>`: токен запоминается в браузере и сразу
убирается из адресной строки. `?admin=` с пустым значением его забывает. Если шлюз стоит за прокси (nginx и т. п.),
все подключения считаются внешними: войти в режим можно только с токеном.

## Одна вкладка на гостя

Пока все входят одним гостевым ключом, сервер при новом входе выбрасывает предыдущее подключение. Поэтому
шлюз сам отдаёт сессию самой новой странице (в любом браузере), а остальные показывают «сессия открыта в другом
окне» с кнопкой «Играть в этом окне» и не переподключаются — иначе две страницы выбрасывали бы друг друга по кругу.
Если шлюз недоступен, страница переподключается сама с нарастающей паузой (3, 6, 12 … 60 с).

## Карта при перемещении

Когда камера сдвигается, сервер досылает окно турфов сообщением 20 (новые клетки по краю). Раньше шлюз его
не понимал и переподключался, чтобы получить карту заново; теперь окно просто прокручивается.

## Чего пока нет

- остальные plane-мастера и `render_target` (параллакс космоса, emissive, размытия), фильтры;
- `animate()` (сообщение 240): значение меняется сразу, без перехода; `glide_size` сервера не учитывается;
- tgui-окна открываются с размером по умолчанию, а не со своим;
- в `input()` нельзя выбрать файл/иконку/звук (такой диалог сразу отменяется);
- уникальные гости: все игроки входят одним и тем же `Guest-4037097759`.

## Важно для SS13

Все игроки шлюза приходят на сервер с `127.0.0.1`. В Paradise это даёт автоматическую админку —
раскомментируйте `DISABLE_LOCALHOST_ADMIN` в `config/config.txt`, прежде чем пускать людей.
